# 城市漫步路线

触发：用户说「City Walk」「城市漫步」「帮我规划一条散步路线」「周末想走走看看」「沿路有什么厕所/麦当劳」等。

## 先补齐信息（缺了才问，最多问两句）
- 城市或大致区域（用户没说、记忆里也没有时再问，不要猜具体地址）
- 可用时长（1 小时 / 半天）和出发时间
- 有没有必去点或主题（老建筑、江边、公园、夜景）

## 规划原则
1. 通行偏好默认取记忆 `profile`：地铁优先、尽量少步行；用户当次说的优先于记忆。
2. 路线组织成「地铁到起点 → 步行串景点 → 地铁离开」，单段步行控制在 15 分钟内；超过就拆段或改乘地铁/公交。
3. 景观按地理位置聚类，不来回折返；优先免费、开放式的公园、滨水步道、观景台、历史街区。
4. 只用高德返回的真实地点与耗时；没查到就写「地图未返回」，不要编店名、门票、营业时间。

## 效率守则（务必遵守，减少工具调用）
1. **不要重复地理编码**：`maps_text_search`（关键词搜索）和 `maps_around_search`（周边搜索）返回的 POI 已带 `location` 经纬度，直接用，不要再调 `maps_geo` 重新解析同一地点。
2. **坐标拿到就缓存复用**：同一个地点的经纬度在本轮对话里只查一次，后续距离计算、路径规划都复用。
3. **一轮批量调用**：能并行的工具（如同时搜厕所、便利店、地铁口）放在同一轮一起调，不要分多轮。
4. **`maps_distance` 可一次传多对起终点**：用 `origins` 和 `destinations` 的 `|` 分隔批量测距，不要一对对单独调。
5. **先搜再测距离**：先用 `maps_around_search` 拿到候选 POI 及坐标，再用 `maps_distance` 批量算距离，不要对每个候选点单独 `maps_geo`。

## 步骤
1. 用 memory_search 查出行偏好和常去区域（关键词：地铁、步行、城市、公园）。
2. 用 `amap__maps_text_search` 把区域/起点解析成坐标**同时**搜景观类 POI；POI 结果里的 `location` 就是坐标，直接用。
3. 对相邻点用 `maps_distance` 批量比较步行距离，选总步行最少、换乘不超过 1 次的组合，记下每段距离和耗时。需要公交/地铁方案时再调 `maps_direction_transit_integrated`。
4. 沿线周边搜索「公共厕所」「便利店」「地铁站出入口」；只保留步行 5 分钟内可达的。
5. 用 `mcdonalds__` 工具取路线 1 公里内门店的名称、地址、距离、营业时间；只作为补给点，不点餐、不下单。
6. 高德服务不可用时，提示用户到「服务」页打开「高德地图」并确认 Key，不要凭印象规划。

## 在高德地图打开路线
先把路线用聊天消息发出来，再调用 phone_task：skill 填 citywalk-map，让高德按「公共交通」打开
（该技能固定用公交/地铁方案，聊天里不要改口说成步行路线）。
goal 按下面的格式给出
（经纬度用上面工具返回的值，不要编；vian 是途经点个数；多个值之间只能用一个竖线 |，不要用逗号或顿号）：
sname=起点名 slat=31.219 slon=121.554 dname=终点名 dlat=31.153 dlon=121.489 vian=2 vialons=121.494|121.472 vialats=31.184|31.183 vianames=中华艺术宫|后滩公园
没有途经点时写 vian=0，三个 via 参数留空。坐标不全就跳过 phone_task，只提醒用户自己在地图里搜。

## 输出格式
**City Walk：{区域}｜约 {时长}｜步行约 {距离}**
1. 去程：{地铁线路} 到 {站名}（{出口}），步行 {X} 分钟
2. {景点 A}：{一句看点}，停留 {X} 分钟；沿线设施：{厕所/便利店/地铁口}
3. {景点 B}：…
4. 补给：麦当劳 {门店名}（{地址}，距路线 {X} 米，{营业时间}）
5. 返程：{地铁线路} 从 {站名} 出发

最后问一句：要不要换成更短或更少步行的方案，或把其中一段改成地铁。

## 边界
- 不编造事实；营业时间、门票、预约要求以工具返回为准，没有就写「未显示」。
- 不替用户买票、点餐、付款；涉及下单先停下等确认。
- 天气或临时闭园无法确认时，提醒出发前再查一次。
